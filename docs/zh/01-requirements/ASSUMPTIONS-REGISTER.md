# 工程假设登记册 (Assumptions Register: DataBlue Next-Gen Platform)

---

## 1. 概述 (Overview)

本文档记录了在阶段 0 期间由于缺少客户工作负载指标而为 **DataBlue 下一代基础设施平台** (`datablue-nextgen-infra-platform`) 所制定的工程与架构假设。

每个假设均被追踪、指定了负责人，并配有验证方法，以确保在阶段 3 IaC 代码生成前获得系统性确认。

---

## 2. 标准化假设日志 (Standardized Assumptions Log)

### `ASM-001`: 微服务容器化就绪度
* **假设**: 跨 5–6 个业务系统的所有约 40 个微服务均已完成容器化（符合 Docker/OCI 规范）、无状态，并支持通过环境变量或 Nacos 进行 12-Factor 应用配置。
* **原因**: 客户指定承载 40 个微服务的 Kubernetes 平台。
* **若假设不成立的影响**: 有状态应用组件将需要专门的持久化卷配置、StatefulSet 或重构。
* **验证方法**: 代码库容器化就绪度审计及微服务仓库 Dockerfile 检查。
* **负责人**: 应用开发负责人 / 主架构师
* **状态**: 开启 / 待验证

---

### `ASM-002`: AWS 账号层级环境隔离
* **假设**: 测试环境与生产环境将部署在 AWS Organization 下的独立 AWS 账号中（如 `DataBlue-Test-Account` 和 `DataBlue-Prod-Account`）。
* **原因**: 标准云安全治理禁止在未经高管特许的情况下，通过 Namespace 将测试和生产混合部署在单个 EKS 集群中。
* **若假设不成立的影响**: 单集群混部将导致严重的爆炸半径风险、嘈杂邻居性能干扰以及数据安全合规漏洞。
* **验证方法**: 安全架构签署及 AWS 账号结构确认。
* **负责人**: 云安全负责人 / 企业架构师
* **状态**: 建议基线 / 待批准

---

### `ASM-003`: EKS 多可用区高可用拓扑
* **假设**: EKS 工作节点和有状态中间件将在单个 AWS 目标区域（如 `us-east-1` 或 `ap-southeast-1`）内的至少 3 个可用区 (3 AZs) 间分布。
* **原因**: 满足高可用性 (HA) 需求 (`NFR-001`) 的必要拓扑。
* **若假设不成立的影响**: 单 AZ 或双 AZ 部署在 AWS 可用区发生故障时具有更高的控制平面/工作节点停机风险。
* **验证方法**: 区域 AWS AZ 配额校验及 VPC 子网拓扑规划审查。
* **负责人**: 基础设施主架构师
* **状态**: 草案 / 评估中

---

### `ASM-004`: 中间件架构策略评估
* **假设**: 在确定有状态服务架构前，将通过正式 ADR 评估 AWS 托管服务（RDS MySQL、ElastiCache Redis、MSK/DocumentDB）与 EKS 自建 Operator 托管方案。
* **原因**: 客户指定了 MySQL、RabbitMQ、MongoDB、Redis 和 Nacos，但未指出对 AWS 托管 vs K8s 自建的偏好。
* **若假设不成立的影响**: 过早承诺自建将增加运维负担；完全承诺 AWS 托管将增加厂商绑定及潜在云成本。
* **验证方法**: 阶段 1 ADR 权衡评估矩阵 (`OPEN-002`)。
* **负责人**: 数据架构师 / 云基础设施负责人
* **状态**: 开启 / 权衡待定

---

### `ASM-005`: CI/CD 流水线职责分离
* **假设**: GitLab 负责源码触发；Jenkins 编排容器构建、镜像扫描并推送至 AWS ECR；Ansible 执行目标环境配置管理与应用部署指令。
* **原因**: 客户规范书同时提到了 GitLab、Jenkins 和 Ansible。
* **若假设不成立的影响**: 流水线职责混乱、重复构建、配置漂移以及部署发布不协调。
* **验证方法**: CI/CD 工作流架构规范文档批准。
* **负责人**: DevOps 主工程师
* **状态**: 建议 / 待审查

---

### `ASM-006`: 初始默认资源分配模型
* **假设**: 在提供真实服务指标前，微服务基线资源 Request 暂按以下比例建模：`Small` (0.25 vCPU, 0.5 GB RAM), `Medium` (0.5 vCPU, 1.0 GB RAM), `Large` (1.0 vCPU, 2.0 GB RAM)，配比为 50/35/15。
* **原因**: 目前缺少客户提供的容量指标数据 (`OPEN-001`)。
* **若假设不成立的影响**: 一旦提供实测 CPU/RAM 指标，成本估算模型需要重新计算。
* **验证方法**: 阶段 3 测试环境中的基准性能剖析。
* **负责人**: FinOps 分析师 / 云架构师
* **状态**: 临时 / 容量占位符

---

### `ASM-007`: 区域数据传输与存储保留
* **假设**: 日志数据在 CloudWatch/OpenSearch 中保留 30 天，随后通过 S3 生命周期归档至 Glacier；数据库备份采用 7 天每日快照保留策略。
* **原因**: 客户非功能性指标目前缺少具体合规保留窗口。
* **若假设不成立的影响**: 延长保留期需求（如 PCI-DSS/HIPAA 要求 365 天）将显著增加 AWS 存储成本。
* **验证方法**: 客户法务与合规需求签署。
* **负责人**: 合规负责人 / 运维工程师
* **状态**: 开启 / 待确认
